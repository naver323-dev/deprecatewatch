Method, sources and limits

DeprecateWatch is a static archive. It does not call an API at page load, run a database, or guess a date. This page explains exactly where each number comes from and what it does not claim.

Pipeline

  1. Collect. Every source below is fetched once a day by a scheduled job, without an API key, and the raw response is kept unchanged.
  2. Normalise. Cycles, support-end and EOL dates are copied into one schema. A status is computed by comparing the source date with the snapshot date: supported, security-only, eol, or no-eol-date.
  3. Publish. The tables you see, the JSON API and llms.txt are generated from that one file, so the HTML, the JSON and the sitemap cannot drift apart.
  4. Verify. A test suite checks the generated site before it is published: date formats, status/date consistency, JSON schema, duplicate pages, link targets and the FAQ text used in structured data.

What the statuses mean

  • Supported — the published EOL date is in the future and active support has not ended.
  • Security-only — active support has ended but the EOL date is still ahead.
  • End of life — the published EOL date has passed.
  • No EOL date — the upstream project publishes no end-of-life date for that cycle; the site does not invent one.

What this site does not do

  • It does not estimate or interpolate a date. If a source has no date, the row says so.
  • It does not rank vendors, score migration paths or recommend a product. The upgrade path shown on a product page is either the newest cycle that is still inside its published support window, or a replacement the upstream source itself states.
  • It does not claim to be an authoritative record. The vendor is; each row links to the vendor or the upstream dataset.
