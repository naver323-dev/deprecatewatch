Questions this page answers

What is DeprecateWatch?

DeprecateWatch is a static archive of end-of-life and deprecation dates for 489 SDKs, runtimes, frameworks, databases, operating systems and cloud services. It holds 9,417 release cycles and is rebuilt every day from upstream sources. The snapshot on this page is dated 2026-11-18.

Where do the dates come from?

Cycle and support dates come from the endoflife.date API (MIT licensed). AWS Lambda runtime deprecation dates come from the AWS Lambda documentation table. Deprecation announcements come from the Google Cloud release notes feed, the Azure service updates feed, AWS What's New and GitHub release feeds. Every row links to the source it was read from, and no date is estimated or filled in by hand.

How many tracked versions are already end-of-life?

As of 2026-11-18, 7,480 of 9,417 tracked release cycles have passed their end-of-life date, 230 are past active support but not yet at end of life, and 176 reach end of life within the next 90 days.

What does the Security-only status mean?

Security-only means the cycle is past the end of its active support window but its published end-of-life date has not arrived yet, so the upstream project no longer ships regular updates for it. End of life means the published EOL date has passed. No EOL date means the project has not published an end-of-life date for that cycle in the source data.

Does DeprecateWatch recommend which version to upgrade to?

No. Each product page shows two facts only: the newest cycle that is still supported for that product, and any replacement the upstream source itself states (for example a recommended model or successor). We do not rank vendors, score alternatives or issue migration advice.

How fresh is the data and how is it updated?

The snapshot shown here was generated on 2026-11-18T10:43:22+09:00 (Asia/Seoul). A scheduled job re-fetches every source daily and rebuilds these pages, so the as_of date in every table header matches the snapshot you are reading. Machine-readable copies are at /api/eol.json, /api/products.json, /api/upcoming.json and /api/announcements.json.

Using this data

The same snapshot is published as JSON, so an assistant or a script can answer "is X end of life, and when" with a dated value instead of a training-cutoff guess:

  • /api/eol.json — every product with every tracked cycle, support and EOL dates, status and day counts.
  • /api/products.json — one row per product with its current cycle and next deadline.
  • /api/upcoming.json — cycles whose EOL date falls in the next 365 days.
  • /api/announcements.json — vendor deprecation and retirement notes with source links.
  • /llms.txt — a plain-text map of the site for language models.
